- 2026-11-10 — Motor: funções puras em `src/neuralmeter/engine/` (recebem eventos+estado+`now`, sem I/O, sem relógio interno) + wrappers finos que leem DB. Claude 5h = janelas encadeadas: 1ª msg abre janela [t, t+5h); msg após fim abre nova. Lookback 24h. Reset oficial futuro em `provider_state.window_5h_reset_at` sobrescreve (janela = [reset-5h, reset)). Reset oficial passado = ignorado. `is_rate_limited=1` + reset futuro → 100%. Percentual limitado a [0,100].
- 2026-11-10 — Motor ChatGPT: janela deslizante por evento (cada msg expira em `created_at + window` do seu modelo). Limites por modelo em tabela `DEFAULT_CHATGPT_LIMITS` (match por prefixo mais longo, case-insensitive) sobrescrevível por parâmetro `limits`; persistência de overrides fica p/ etapa tray "limites manuais". Modelo desconhecido → janela 3h, teto = `provider_state.window_5h_max_units`. Agregado do provedor (barra HUD) = modelo com maior percentual. `reset_at` por modelo = msg mais antiga ativa + janela (próxima liberação). `is_rate_limited=1` + `window_5h_reset_at` futuro → agregado 100% com reset oficial.
- 2026-11-10 — PREMISSA (sem captura real de limites ChatGPT): defaults `gpt-4o`→3h/80, `gpt-4.1`→3h/80, `gpt-5`→3h/160, `o4-mini`→3h/150, `o3`→5h/100, default 3h. Cotas semanais (RF02) ficam p/ etapa do motor 7d. Valores só estimativa; calibração (RF04.2) ajusta.
- 2026-11-10 — Motor 7d: módulo único `engine/weekly.py` p/ ambos provedores. Histórico rolante = eventos em (now-7d, now]. Agregado: used=Σweight, teto=`provider_state.weekly_max_units`. `reset_at`: `weekly_reset_at` oficial futuro sobrescreve; senão msg mais antiga ativa + 7d (próxima liberação). `is_rate_limited=1` + `weekly_reset_at` futuro → 100% (bloqueio 5h usa `window_5h_reset_at`, independente). Tokens estimados = Σ max(prompt_chars, context_chars) // 4 (heurística ~4 chars/token).
- 2026-11-10 — PREMISSA cotas semanais por modelo (RF02.1), só estimativa: ChatGPT `o3`→100/sem, `o4-mini-high`→700/sem (expandível); Claude sem cota por modelo (só total da conta). Match por prefixo mais longo (reusar `_match_key` → tornar público `match_model_key` em `engine/window.py`). Persistência de overrides = etapa tray "limites manuais".
- 2026-11-10 — Protocolo WS v1 (JSON texto, 1 objeto/frame, campo `type`). Ext→App: `hello{v,client,version}`, `status{tabs:{claude,chatgpt}}`, `usage{provider,model,conversation_id?,prompt_chars,context_chars,ts?}`, `limit{provider,scope:"5h"|"weekly",reset_at(epoch ms),rate_limited?}`, `ping`. App→Ext: `ack{ref?}`, `pong`, `error{reason}`. `ts` epoch ms UTC; ausente/futuro>60s/anterior a 24h → hora do servidor. `weight_units`=1.0 até etapa peso progressivo (RF01.3). Texto do prompt nunca trafega (só contagens). Segurança: bind só `127.0.0.1`; handshake rejeita `Origin` que não seja `chrome-extension://…` (ausente permitido p/ testes/clientes locais); frame máx 64 KB. Motivo: impedir que sites conectem ao WS local via JS.
- 2026-11-10 — Servidor WS: `asyncio` + `websockets` (API `websockets.asyncio.server`) em `threading.Thread` daemon próprio; notifica UI via callback `on_update(kind, payload)` chamado na thread WS (HUD fará ponte p/ Qt signal). Parsing/validação = funções puras em `server/protocol.py` (TDD), aplicação no DB em `server/handler.py`.
- 2026-11-10 — Extensão conexão: service worker (`"type":"module"`) dono do único WS. Lógica pura injetável (`ws_client.js`: fábrica WebSocket + relógio injetados) p/ testar em `node --test` sem browser. Reconexão backoff exponencial 1s→30s (×2, jitter ±20%, reset ao abrir). Keepalive: `ping` a cada 20s (tráfego WS mantém SW vivo, Chrome ≥116) + `chrome.alarms` 1 min reconecta se SW acordar desconectado. Status de abas via `chrome.tabs.query({url})` (host_permissions bastam, sem permissão `tabs`), enviado em `hello` subsequente e a cada `tabs.onUpdated/onRemoved` (debounce 500ms) só se mudou. Formato `status{tabs:{claude:bool,chatgpt:bool}}`. Badge: sem conexão = "OFF" cinza; conectado sem abas = "…" amarelo; conectado + aba = "" verde. Fila de saída máx 100 msgs enquanto offline (descarta mais antigas). Permissões: `alarms` apenas.
- 2026-11-10 — Captura passiva (arquitetura, reusada p/ ChatGPT): content script `world:"MAIN"` `document_start` envolve `window.fetch` (retorna a MESMA promise original; lê só `resp.clone()`; erros engolidos; nunca altera request/response nem faz requisição própria) e repassa dados crus via `window.postMessage({__nm:1,...})`. Content script ISOLATED (`bridge.js`, classic) filtra `event.source===window`, carrega lógica pura via `import(chrome.runtime.getURL(...))` (arquivos em `web_accessible_resources` só p/ os hosts alvo), emite só contagens/metadados p/ SW via `chrome.runtime.sendMessage({nm:"usage"|"limit",payload})`. SW aceita só de `sender.tab.url` claude.ai/chatgpt.com, sanitiza (whitelist de campos/tipos) e `client.send`. Texto do prompt nunca sai do content script. Modo debug: `localStorage.neuralmeterDebug="1"` na aba → `console.debug("[NeuralMeter]", ...)` de campos/eventos desconhecidos (só local, p/ calibrar PREMISSAs).
- 2026-11-10 — PREMISSA Claude (sem HAR real): envio = `POST /api/organizations/{org}/chat_conversations/{conv}/completion` (também `/retry_completion`), body JSON `{prompt, model?, attachments?[{extracted_content}], files?}`; sem `model` → `"claude-unknown"`. Resposta SSE (`event:`/`data:` JSON): `message_start.message.model`, `content_block_delta.delta.text` (conta chars resposta), `message_limit.message_limit{type:"within_limit"|"approaching_limit"|"exceeded_limit", resetsAt (epoch s), windows?{"5h"|"7d":{status,resets_at}}}`. 429 body `{error:{type:"rate_limit_error",message:<string JSON {type,resetsAt}>}}`. Mapeamento: `exceeded_limit` → `rate_limited:true`; janela `7d` → `scope:"weekly"`, demais → `"5h"`; `reset_at` s→ms. Contexto (RF01.3 base): rastreador por conversa na aba (Map LRU 50) acumula prompt+anexos+resposta; `context_chars` = acumulado anterior + prompt atual; recarregar aba zera (aceito; calibração depois). `usage` emitido no envio (latência RNF02), não espera resposta.
- 2026-11-10 — PREMISSA ChatGPT (sem HAR real): envio = `POST /backend-api/conversation` ou `/backend-api/f/conversation` (sem sufixo; ignora `/conversation/init`, `/prepare`, GETs). Body JSON `{action:"next"|"variant"|"continue", model?, conversation_id?, messages:[{author:{role:"user"},content:{content_type,parts:[string|obj]}}]}`; chars = Σ parts string (obj ignorado); sem `model` ou `"auto"` → modelo do SSE se vier antes do fim, senão `"gpt-unknown"`; emitir `usage` no envio (RNF02) com modelo do body (fallback `"gpt-unknown"`). `conversation_id` ausente (conversa nova) → id do 1º evento SSE com `conversation_id`; tracker indexado pelo id final. SSE: linhas `data:` JSON até `data: [DONE]`; formato v1 (`event: delta` + `{o,p,v}` JSON-patch: `v` string em `p` contendo `/message/content/parts` ou `o:"append"` conta chars) e legado (`{message:{author.role:"assistant",content.parts[0]}}` acumulado → usar maior comprimento visto). 429 / 4xx body `{detail:{code:"model_cap_exceeded"|"rate_limit_exceeded", clears_in(s)?, reset_at?(s ou ISO)}}` ou `detail` string → `limit{provider:"chatgpt",scope:"5h",reset_at,rate_limited:true}` se reset derivável; senão `onUnknown`. Hook `page_hook.js` passa a casar URL por regex por host (claude `/completion`, chatgpt `/backend-api/(f/)?conversation$`). SW valida provider == host do `sender.tab.url` (impede aba claude emitir como chatgpt).
- 2026-11-10 — HUD base: pacote `src/neuralmeter/ui/`. Lógica pura sem Qt (`ui/snap.py`: retângulos como tuplas `(x,y,w,h)`) p/ TDD; widgets Qt finos. Sem QSettings (registro Windows dificulta teste/portabilidade). Testes Qt: `QT_QPA_PLATFORM=offscreen`, sem pytest-qt (fixture `QApplication` própria em `tests/conftest.py`).
